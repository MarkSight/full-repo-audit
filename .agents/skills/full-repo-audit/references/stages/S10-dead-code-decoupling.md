# S10 死代码 / 重复 / 解耦

扫描未被使用的代码和结构性技术债务。**每个维度一轮。** 开始本阶段前读 S05、S08、S09 摘要。

删除前必须检查动态引用：字符串路由、反射、配置文件中引用的名字、插件自动发现。

---

## 死代码

## S10.01 未使用的导出

- 全仓搜索无引用的导出函数、类、常量、类型
- 排除动态引用后确认

## S10.02 废弃兼容分支与不可达代码

- 数据已全部迁移后仍保留的旧格式处理分支
- 永远为假的条件、已过期的版本判断
- 已下线功能的残留代码

## S10.03 只被测试引用的生产代码

- 生产代码中只有测试在调用的函数
- 判断：是该删的遗留代码，还是测试在测没人用的东西

## S10.04 注释掉的代码与一次性脚本

- 注释掉的代码块
- 已经执行过、不会再用的一次性脚本
- 废弃的工具与调试代码

## S10.05 未使用与未声明的依赖

- 清单中声明但代码中未引用的依赖
- 代码中引用但清单中未声明的依赖（靠传递依赖碰巧可用）
- devDependencies 被生产代码引用

## 重复

## S10.06 重复的函数实现

- 跨文件的相同或近似函数实现
- 同一语义重复 3 处及以上才建议抽象；只是写法相似、语义不同的不要合并

## S10.07 重复的数据访问

- 相似的数据库查询散落在多处
- 是否应收敛到数据访问层

## S10.08 重复的校验与权限逻辑

- 同一校验规则在多处各写一遍
- 同一权限判断在多处各写一遍（优先级最高：某处被修、某处没修）

## S10.09 过度抽象

- 只有一个实现的接口
- 为假设的未来需求做的参数化
- 多层包装只为调用一个函数

## 解耦

## S10.10 共享包中的业务逻辑

- 共享 / 公共包中混入的特定业务逻辑
- 共享包引入的重量依赖污染所有使用方

## S10.11 大文件按职责拆分

- 超过 500 行的文件，按职责给出拆分方案，不按行数机械切分
- 同一文件同时做请求解析、业务规则、持久化、格式化
- 拆分方案给出目标结构与分步顺序，每一步都能独立运行、独立回滚

## S10.12 硬编码依赖

- 无法在测试中替换的直接构造
- 写死的路径、URL、租户、语言、时区
- 分散在各处的同类工具函数
