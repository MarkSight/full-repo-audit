# S05 QA 查漏补缺

从 QA 视角检查遗漏，并确认前四个阶段的修复没有引入回归。**每个维度一轮。**

开始本阶段前读 S01-S04 摘要，并准备修复 diff：`git diff <起始 commit>`。

---

## 回归

## S05.01 修复引起的签名与返回形态变化

**定位**：S01-S04 的修复 diff 中被修改的函数、接口、类型。

- 函数签名、返回形态、错误类型是否改变
- 所有调用方是否都已适配（全仓搜索调用点）
- 对外 API 的响应是否改变

## S05.02 修复的连锁副作用

**定位**：S01-S04 的修复 diff。

- 事务相关修复是否在事务内引入了异步 IO
- 网络 / SSRF 相关修复是否引入了连接泄漏
- 错误边界、错误页修复对其他页面的影响
- 权限、审批类修复是否影响了其他流程

## S05.03 用户旅程端到端

**定位**：从产品中挑 3-5 条主要用户旅程（例如：创建 → 编辑 → 生成 → 选择 → 导出）。

**每条旅程单独作为一轮**（S05.03-1、S05.03-2……），在 progress.md 中分别列出。

- 沿代码路径逐步走：界面事件 → API → 服务 → 存储 → 回显
- 每一步的失败分支是否有处理，失败后状态能否恢复
- 步骤之间交接的数据字段是否一致

## 边界

## S05.04 空值、超长与特殊字符

**定位**：API 入口、表单处理、导入功能。

- 空值、空字符串、空数组
- 超长字符串、极大数字、深层嵌套
- 特殊字符、emoji、多字节字符、换行符

## S05.05 并发重复请求与快速连点

**定位**：创建、提交、支付、生成类操作。

- 同一请求并发发送多次的结果
- 快速连续点击触发多次操作
- 前端防抖与后端去重是否都有

## S05.06 下游故障注入

**定位**：依赖数据库、缓存、第三方 API 的关键路径。

- 下游超时时的表现
- 下游返回错误或异常数据时的表现
- 下游完全不可用时是否整体崩溃

## 一致性与完整性

## S05.07 API 响应格式一致性

**定位**：所有 API 的响应构造。

- 成功响应结构是否统一
- 错误响应结构是否统一
- 分页、列表响应结构是否统一

## S05.08 未使用代码与透传断裂

**定位**：全仓源码。

- 未使用的导入、变量、参数
- props / 参数在传递链中途断掉或被忽略

## S05.09 循环依赖与内部包引用

**定位**：模块 import 图、monorepo 内部包的依赖声明。

- 循环依赖
- 内部包是否使用 workspace 协议引用
- 内部包之间的版本是否一致

## S05.10 TODO / FIXME 逐条归类

**定位**：全仓的 TODO、FIXME、HACK、XXX。

逐条归入以下一类并处理：
- 真实缺陷 → 转为正式发现
- 已经过期 → 删除
- 有效待办 → 记入未修清单
- 没有信息量 → 删除

## 可观测性

## S05.11 catch 块日志上下文

**定位**：所有 catch / except 块。

- 是否记录了足够定位问题的上下文（哪个用户、哪个资源、什么参数）
- 是否只记录了 message 而丢失了堆栈
- 同一错误是否在多层重复记录

## S05.12 审计事件

**定位**：权限变更、数据导出、删除、管理员操作、支付等敏感操作。

- 是否记录审计事件
- 记录内容是否包含谁、做了什么、何时、从哪里
- 审计记录与普通日志是否分离

## S05.13 启动日志与健康检查

**定位**：服务启动流程、健康检查接口。

- 启动时是否记录关键配置（脱敏后）与依赖连接结果
- 健康检查是否真正检查了依赖
- 存活检查与就绪检查是否区分

## S05.14 指标与告警

**定位**：指标埋点、监控配置、告警规则。

- 关键路径的成功率、延迟、错误率是否可观测
- 后台任务失败是否有人会知道
- 指标标签基数是否可控（用户 ID 作为标签会爆炸）
