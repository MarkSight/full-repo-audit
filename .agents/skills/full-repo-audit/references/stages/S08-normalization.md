# S08 规范化统一

统一代码风格和规范。**每个维度一轮。** 开始本阶段前读 S05 摘要。

**以仓库现有的多数派约定为准**，每条发现写明「现有约定是什么，这里如何偏离」。
能交给格式化 / lint 工具自动解决的问题，只报一条「未启用 / 未强制」，不逐处列举。

---

## 路径与命名

## S08.01 目录与文件命名

- 目录命名风格（kebab-case / snake_case / camelCase）是否统一
- 文件名与其主要导出是否一致
- 同类文件的命名后缀是否统一（`.service`、`.controller`、`.hook` 等）

## S08.02 扩展名与路由路径风格

- 文件扩展名选择是否一致（如 `.ts` 与 `.tsx`、`.js` 与 `.mjs`）
- API 路由路径风格（复数、大小写、层级）是否统一

## S08.03 函数、组件与类型命名

- 函数是否为「动词 + 名词」
- 组件 / 类名与文件名是否一致
- 类型、接口、枚举、常量的命名风格
- 缩写使用是否一致

## S08.04 布尔与事件处理前缀

- 布尔变量与函数的前缀（is / has / should / can）
- 事件处理函数前缀（handle / on）
- 集合变量是否使用复数

## 导入导出

## S08.05 导入排序与类型导入

- 导入排序与分组规则
- 类型导入写法是否统一
- 路径别名与深层相对路径的使用

## S08.06 导出方式与桶文件

- 命名导出与默认导出的选择
- 桶文件（index 全量导出）的使用策略
- 同一模块是否既有命名导出又有默认导出

## 代码风格

## S08.07 错误处理风格

- 返回 Result 还是抛异常，同一层是否统一
- 自定义错误类是否带 code 字段
- 错误构造方式是否统一

## S08.08 空值合并与默认值

- `??` 与 `||` 的误用（0、空字符串被当作缺省）
- 默认参数与解构默认值的写法
- 可选链的滥用掩盖了本应报错的情况

## S08.09 框架惯用写法

**定位**：框架相关代码。无对应框架时跳过。

- 记忆化（如 useCallback / useMemo）的滥用与缺失
- 副作用、生命周期的写法是否统一
- 状态管理方式是否统一

## 注释

## S08.10 公共 API 文档注释

- 对外暴露的函数、类型是否有用法说明
- 参数约束、返回值、可能抛出的错误是否说明

## S08.11 抑制注释

- lint / 类型检查的抑制注释是否写明理由
- 抑制范围是否最小化（行级而非文件级）

## S08.12 过期与错误注释

- 与代码行为不一致的注释（比没有注释更糟）
- 复述代码、没有信息量的注释
- 注释掉的代码

## 测试与配置规范

## S08.13 测试描述与文件位置

- 测试描述格式是否统一，是否说明「在什么条件下期望什么」
- 测试文件位置（同目录 / 独立 tests 目录）是否统一
- 测试文件命名是否统一

## S08.14 各包配置与脚本名

**定位**：monorepo 各包的编译配置、manifest、脚本定义。

- 各包编译配置、lint 配置是否一致
- 脚本名语义是否统一（`test`、`check`、`build` 在各包含义相同）
- 环境变量命名风格是否统一

## 跨包接口

## S08.15 数据访问签名与参数顺序

- 数据访问函数的签名风格是否一致
- CRUD 函数的参数顺序是否一致（如 id 在前还是在后）
- 分页、过滤参数的传递方式

## S08.16 共享类型、废弃 API 与导出面

- 同一类型在多个包中重复定义
- 已废弃但仍被使用的 API
- 本应内部使用却被导出的函数
