# S07 测试清理优化

清理测试代码中的技术债务。**每个维度一轮。** 开始本阶段前读 S06 摘要。

审查 agent 先输出清理清单，修复阶段再执行。**删除测试必须写明理由，并确认原本守护的行为仍有测试覆盖。**

---

## S07.01 文本扫描测试迁移

**定位**：读取源文件内容再断言字符串的测试（如 `readFileSync` + `toContain`），S04.12 已列出清单。

- 纯 CSS 类名断言：删除
- 确实需要守护的约定：合并为少量 tripwire 测试，注明守护什么
- 其余：迁移为行为测试

## S07.02 硬编码计数测试

**定位**：断言文件数、skill 数、迁移数、路由数等数量的测试。

- 每次新增内容都必须改测试的计数断言
- 改为结构性断言（例如「每个 X 都有 Y」），或删除

## S07.03 引用已删除 API 的测试

**定位**：全部测试文件。

- 引用已删除或已重命名的函数、模块、接口
- 测试已不再对应任何现存行为

## S07.04 长期 skip、todo 与 only

**定位**：`skip`、`todo`、`only`、`xit`、`xdescribe` 等标记。

- `only` 泄漏进主干会导致其余测试全部不运行，优先处理
- 长期 skip / todo 的测试：修复，或删除并写明理由

## S07.05 重复测试

**定位**：全部测试文件。

- 相同的 describe / it 描述
- 跨应用、跨包重复的测试
- 同一行为在单测与 e2e 中各测一遍（保留更有价值的一层）

## S07.06 重复 fixture 与 setup

**定位**：fixture、测试工具函数、beforeEach / beforeAll。

- 近似重复的 fixture
- 每个测试文件手写的相同 setup 代码
- 可以提取为共享工厂函数的测试数据构造

## S07.07 弱断言强化

**定位**：S06.03 中列出的弱断言。

- `toBeDefined` → `toEqual` 具体值
- `toBeTruthy` → 具体匹配
- `toContain` → 精确匹配（在合适时）
- 浮点数比较 → `toBeCloseTo`

## S07.08 过大快照拆分

**定位**：快照文件与快照断言。

- 整页 / 整个组件树的大快照（任何改动都要更新，没人认真审查）
- 拆分为针对关键内容的具体断言
