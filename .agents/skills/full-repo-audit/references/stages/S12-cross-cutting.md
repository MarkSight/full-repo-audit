# S12 跨切面治理

检查纵向一致性：同一件事在全仓是否只有一种做法。**每个维度一轮。** 开始本阶段前读 S01-S11 摘要。

---

## 错误

## S12.01 错误码格式

- 所有错误类的 code 字段格式是否统一
- 用 message 字符串当错误码来判断的地方（改文案会静默破坏调用方）
- 缺少 code 字段的错误类

## S12.02 错误码映射

- 错误码到 HTTP 状态码 / 退出码的映射是否一致
- 错误码到用户可见文案的映射是否完整，是否有兜底文案
- 同类错误是否被映射成不同的状态码

## 日志

## S12.03 日志前缀与统一 logger

- console / print 调用的 `[topic]` 前缀覆盖率
- 没有前缀的日志清单
- 是否经由统一的 logger，还是散落的裸调用

## S12.04 日志级别与噪音

- 日志级别的使用是否合理（正常流程不打 error）
- 高频重复日志
- 同一错误在多层各记录一遍

## S12.05 日志脱敏

- 是否有统一的脱敏函数或敏感字段清单
- 还是依赖每个调用点自觉处理

## 通用模式

## S12.06 日期格式与 now()

- API 响应中的日期格式是否统一（带时区的 ISO 8601）
- 是否使用共享的 now() / 时钟抽象，还是到处直接取系统时间

## S12.07 分页模式

- 分页参数名、默认值、上限是否统一
- 分页返回结构是否统一
- offset 分页与游标分页的选择是否一致

## S12.08 外部调用封装

- 外部 HTTP / 第三方 SDK 调用是否经过统一封装
- 超时、重试退避、错误转换、日志是否在封装中统一处理
- 绕过封装的裸调用清单

## S12.09 ID 生成

- ID 生成方式是否统一（自增、UUID 版本、自定义）
- 用于安全场景的 ID 是否不可猜测

## 门禁

## S12.10 高频问题固化为门禁

**定位**：S01-S11 摘要中的「高频问题类型」。

- 逐个判断能否写成 lint 规则、测试或 CI 检查
- 能写的直接落地，并确认：误报少、运行快、失败信息能指导修复
- 不能自动化的，写进贡献文档或 PR 模板

## S12.11 失效门禁排查

**定位**：CI 配置、lint 配置、测试配置、提交钩子。

- `continue-on-error`、被注释掉的检查
- lint / 类型检查排除了大范围目录
- 覆盖率等阈值低于当前实际值
- 长期失败、无人处理的检查
