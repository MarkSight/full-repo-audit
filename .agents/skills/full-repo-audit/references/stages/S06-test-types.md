# S06 测试类型深挖

专注测试体系本身。**每个维度一轮。** 开始本阶段前读 S04（测试模式与覆盖缺口）、S05 摘要。

---

## S06.01 集成测试的依赖与清理

**定位**：集成测试、e2e 测试及其 setup / teardown。

- 使用真实依赖、可信替身，还是全部 mock
- setup 创建的数据、文件、进程是否在 teardown 中清理干净
- 测试数据库是否与其他测试隔离

## S06.02 关键 API 路径覆盖映射

**定位**：API 路由清单与测试文件。

- 逐个列出关键 API，标注有无测试
- 有测试的是否覆盖了失败分支（校验失败、无权限、不存在）

## S06.03 弱断言

**定位**：全部测试文件。

- `toBeDefined`、`toBeTruthy`、`not.toThrow`
- 只断言状态码，不断言响应体
- 只断言 `length > 0`、只断言调用次数

## S06.04 无断言与不执行的断言

**定位**：全部测试文件。

- 只执行代码、没有任何断言的测试
- 断言写在可能不会被执行的回调里（异步测试陷阱）
- 断言写在 try 块里，异常被 catch 吞掉

## S06.05 变异抽查

**定位**：关键模块的测试，以及 S06.03 / S06.04 中可疑的测试。

- 故意改坏被测实现（反转条件、删掉一行、改返回值）
- 测试是否会失败；不会失败的测试记为发现
- 抽查完成后恢复实现

## S06.06 mock 泄漏与全局替换

**定位**：mock、stub、spy、全局对象替换。

- fetch、时钟、随机数、环境变量、全局对象的替换是否在测试后恢复
- mock 的响应结构是否与真实接口一致
- mock 的是外部依赖，还是被测模块的内部实现

## S06.07 fixture 与 schema 同步

**定位**：fixture 文件、测试数据工厂、seed 数据。

- fixture 字段与当前 schema 是否一致
- 近似重复的 fixture
- fixture 中是否含真实用户数据

## S06.08 测试间污染与顺序依赖

**定位**：共享状态、全局 setup、模块级缓存。

- 单独运行、乱序运行、重复运行是否仍然通过
- 一个测试修改的全局状态是否影响其他测试
- 并行运行时的端口、临时目录、数据库冲突

## S06.09 不稳定因素

**定位**：全部测试文件。

- 固定时长的 sleep 等待
- 依赖真实网络或第三方服务
- 依赖当前时间、时区、随机数、map 迭代顺序
- 已知时好时坏但被忽略或靠重试掩盖的测试

## S06.10 认证与授权测试

**定位**：受保护接口的测试。

- 未登录访问受保护接口的测试
- 用户 A 访问用户 B 资源应被拒绝的测试（授权矩阵）
- 不同角色访问管理接口的测试

## S06.11 注入与外连安全测试

**定位**：输入校验、文件操作、外部请求相关的测试。

- SQL / 命令注入测试
- 路径遍历测试
- SSRF 测试（含重定向到内网地址）
- XSS 测试

## S06.12 限流与超大请求测试

**定位**：限流、请求大小限制相关的测试。

- 超过限流阈值的测试
- 超大请求体、超大上传的测试
- 超大分页参数的测试

## S06.13 缺失测试类型盘点

**定位**：测试目录结构与测试配置。

逐项判断是否缺失：视觉回归、API 契约、性能基准、模糊 / 属性测试、a11y 自动检查、
组件交互测试、迁移测试、并发测试。每个缺失的类型给出：
- 是否值得加
- 缺失的影响
- 最小起步方案（先覆盖哪 1-2 个场景）
