# S09 完整性验证

前八个阶段改动量大（尤其 S07 测试清理、S08 规范化）。在 S10 开始删除代码之前，做一次全面验证。

**每个维度一轮。** 本阶段的审查 agent 负责运行命令、定位失败根因；修复仍按单轮流程 ⑥ 由修复 agent 完成，修完重跑，直到通过。
**不允许用跳过测试、忽略规则、放宽配置的方式让门禁变绿。**

---

## S09.01 全量类型检查

- 运行 typecheck（Phase 0 确定的命令）
- 逐个错误定位根因，区分是哪个阶段的修复引入

## S09.02 全量 lint

- 运行 lint，目标零错误
- 本次审查新增的抑制注释是否都写明了理由

## S09.03 全量测试

- 运行全部测试，目标全部通过
- 失败的测试区分三类分别处理：代码被改坏 / 测试本身过期 / 不稳定
- 不直接删除失败的测试

## S09.04 构建

- 运行 build（无 build 步骤时跳过）
- 构建告警是否比起始 commit 时增加

## S09.05 跨阶段冲突检测

- S01-S08 的修复之间是否冲突：同一契约被两处反向修改，同一文件多次修改后逻辑互相覆盖
- 注册表、所有权清单、契约测试、快照 / hash 是否已随修改更新
