# S14 终验闭环

最终验证。**每个维度一轮。** 开始本阶段前读 S01-S13 全部摘要与 `audit/progress.md`。
需要运行命令的维度，审查 agent 负责运行并定位失败根因；修复仍按单轮流程 ⑥ 由修复 agent 完成。

**不允许用跳过测试、忽略规则、放宽配置、`--no-verify` 的方式通过验证。**

---

## S14.01 全链回归

- 运行全部门禁：format → lint → typecheck → test → build
- 仓库有 `validate` 之类的聚合命令时优先使用
- 失败时定位根因、修复、重跑，直到全部通过

## S14.02 修复可审计性

- CHANGELOG / fixlog 是否记录了本次审查的修复
- 每项重要修复能否从记录追溯到改动的文件

## S14.03 已修项回归确认

- 逐条回看 `progress.md` 中已修复的 Critical / High 发现
- 确认修复仍然有效，没有被后续维度的改动覆盖或回退

## S14.04 文档目录完整性

- 本次审查新增或修改的文档是否放在正确位置
- 文档索引是否更新，内部链接是否有效

## S14.05 汇总报告与提交

1. 合并 S01-S14 阶段摘要为 `audit/REPORT.md`：
   - 各阶段：跑过的维度数、跳过的维度数及原因、发现数、修复数
   - 未修复清单及原因
   - S12 新增的门禁
   - 需要人工处理的事项（凭据轮换、数据迁移、依赖大版本升级）
2. 按仓库协作规范 commit、push、创建 PR。
