# S02 深度交叉审查

安全、事务、可访问性、错误处理、性能五个方面，**拆成细粒度维度，每个维度一轮**。

开始本阶段前读 S01 摘要，把高频问题写进相关维度的 agent prompt。

---

## 安全：认证

## S02.01 认证覆盖

**定位**：路由 / handler 注册处、认证中间件。

- 逐个列出所有入口，确认每个是否经过认证
- 认证中间件是「默认拒绝、白名单放行」还是「默认放行、逐个加保护」
- 新增路由是否会自动受保护
- 静态文件、健康检查、webhook 等例外入口是否确实应该公开

## S02.02 会话与 token 生命周期

**定位**：登录、登出、会话存储、token 签发与校验。

- 会话 / token 的过期时间与续期策略
- 登出后服务端是否真正失效（而不只是删除客户端 cookie）
- JWT：算法固定、签名校验、`exp` / `aud` / `iss` 校验
- token 存放位置与泄露面

## S02.03 口令、重置与账号枚举

**定位**：注册、登录、找回密码、修改密码。

- 口令哈希算法与参数（bcrypt / scrypt / argon2）
- 重置 token：一次性、短期有效、绑定用户、不可猜测
- 登录 / 注册 / 重置的响应是否泄露「账号是否存在」
- 登录失败的限速与锁定

## S02.04 OAuth 与 SSO

**定位**：第三方登录回调、token 交换、账号绑定。无第三方登录时跳过。

- `state` 参数与 PKCE
- redirect_uri 白名单
- token 交换是否在服务端完成
- 按邮箱自动绑定已有账号时，是否校验邮箱已验证（否则可接管账号）

## 安全：授权

## S02.05 IDOR 与资源归属校验

**定位**：所有按 ID 读取、修改、删除资源的查询。

- 每个查询是否带上归属条件（用户 / 租户 / 组织）
- 「先查出资源再判断权限」时，判断失败前是否已经泄露信息
- 返回 404 还是 403，是否泄露资源存在性
- 关联资源（子资源、附件）是否继承了父资源的归属校验

## S02.06 权限集中度与功能级越权

**定位**：权限判断函数、角色定义、管理接口。

- 权限判断集中在一层，还是散落在各 handler（散落必有漏）
- 批量接口是否与单条接口做了同等校验
- 界面隐藏了入口，但 API 仍可直接调用
- 响应中是否返回了调用者无权查看的字段
- 管理、调试、内部接口是否暴露且缺少认证

## S02.07 多租户隔离

**定位**：租户 / 组织 ID 的获取与使用、共享缓存、队列、搜索索引。无多租户时跳过。

- 租户 ID 是从会话中取，还是从请求体 / 参数中取（后者可伪造）
- 缓存键是否包含租户维度
- 队列消息、搜索索引、对象存储路径是否按租户隔离
- 跨租户的关联是否可以被构造

## 安全：输入与外连

## S02.08 SQL 与 NoSQL 注入

**定位**：所有拼接查询的位置、ORM 的原生查询入口。

- 字符串拼接或模板拼接 SQL
- 动态表名、列名、排序字段的来源
- `LIKE` 通配符未转义
- NoSQL 操作符注入（如 `$where`、`$gt` 来自用户输入）

## S02.09 命令注入与子进程

**定位**：`exec` / `spawn` / `system` / `subprocess` / `Command` 调用。

- 参数是否来自用户输入或外部数据
- 是否用 shell 模式拼接字符串（应改为参数数组）
- 可执行文件路径是否可被控制

## S02.10 路径遍历与文件操作

**定位**：文件读写、静态文件服务、上传保存、压缩包解压。

- 用户输入参与文件路径拼接
- 解压时的 `../` 条目（zip slip）
- 上传文件名是否规范化
- 符号链接跟随

## S02.11 XSS 与不安全渲染

**定位**：原始 HTML 渲染、markdown 渲染、用户内容展示。

- `innerHTML` / `dangerouslySetInnerHTML` / `v-html` 等原始渲染
- markdown 渲染是否 sanitize
- 用户提供的 URL 进入 `href` / `src`（`javascript:` 协议）
- SVG 上传与内联

## S02.12 SSRF 与外部请求

**定位**：所有根据用户输入或外部数据发起 HTTP 请求的代码（webhook、抓取、导入、回调）。

- 协议白名单
- 内网地址、回环地址、云元数据地址（169.254.169.254）的拦截
- **重定向之后是否重新校验目标地址**
- DNS 解析后再校验（防 DNS rebinding）
- 请求超时与响应体大小上限

## S02.13 反序列化、eval 与模板注入

**定位**：反序列化调用、`eval` / `new Function`、服务端模板渲染、YAML 解析。

- 不可信数据的反序列化（pickle、Java 序列化、`yaml.load`）
- 动态代码执行的输入来源
- 用户输入进入模板字符串
- 原型污染（`__proto__`、`constructor`）

## S02.14 CSRF、CORS 与 Cookie

**定位**：会改变状态的接口、CORS 配置、cookie 设置。

- 状态变更请求有无 CSRF 防护；GET 请求是否会改状态
- CORS 是否反射任意 Origin，或 `*` 配合 credentials
- cookie 的 `HttpOnly` / `Secure` / `SameSite`
- 开放重定向（登录后跳转参数）

## S02.15 敏感数据暴露

**定位**：API 响应序列化、错误处理器、日志调用。

- 响应返回了多余字段（密码哈希、内部 ID、其他用户信息）
- 错误信息泄露堆栈、SQL、内部路径
- 日志打印 token、cookie、完整请求体
- URL 中携带敏感参数（会进入日志与 Referer）

## S02.16 密码学与随机数

**定位**：加密、签名、哈希、随机数生成调用。

- MD5 / SHA1 用于安全场景、ECB 模式、固定 IV
- 用非密码学随机数生成 token、邀请码、ID
- TLS 证书校验被关闭
- 签名比较是否恒定时间

## S02.17 Webhook 入站校验

**定位**：接收第三方回调的接口。无入站 webhook 时跳过。

- 签名校验是否存在，是否覆盖完整原始 body
- 时间戳防重放
- 重复投递的幂等处理
- 校验失败的日志与响应

## 事务与数据完整性

## S02.18 多步写入的事务边界

**定位**：所有包含多条写操作的函数。

- delete + insert、主表 + 关联表是否在同一事务
- 批量写入部分失败时的语义（全部回滚 / 部分成功并报告）
- 事务失败后已发生的副作用（已发邮件、已写文件）

## S02.19 事务透传与事务内外部 IO

**定位**：开启事务的函数及其调用链。

- 事务对象是否一路传到下层函数，下层是否偷偷用了全局连接
- 事务内部是否发起 HTTP、AI 调用、文件写入等外部 IO
- 长事务占用连接的风险

## S02.20 TOCTOU 与唯一性竞态

**定位**：「先查后写」的代码（查重后插入、查余额后扣减、查状态后修改）。

- 检查与写入之间是否有原子保障（唯一约束、条件更新、锁）
- 唯一性是否只靠应用层判断，数据库没有约束
- 并发请求下能否产生重复数据

## S02.21 幂等性与重复提交

**定位**：创建类接口、支付 / 扣费、队列消费者、webhook 处理。

- 客户端重试、用户双击、消息重投时的后果
- 是否有幂等键
- 队列消费者在至少一次投递语义下是否幂等

## S02.22 双写一致性

**定位**：写数据库的同时写缓存、搜索索引、对象存储、消息队列的代码。

- 一边成功一边失败时的处理
- 写入顺序是否会导致短暂或永久不一致
- 有无补偿、重试或 outbox 机制

## 可访问性与 i18n（无 UI 时整组跳过）

## S02.23 键盘可达与焦点管理

- 所有交互元素能否用 Tab 到达并激活
- 焦点顺序是否符合视觉顺序，有无键盘陷阱
- 弹窗打开时焦点移入，关闭时归还；Esc 关闭
- 路由切换后焦点位置
- 焦点样式是否可见

## S02.24 语义、aria 与屏幕阅读器

- 图标按钮是否有可读名称
- 表单 label 与输入框关联；错误信息与字段关联
- 自定义控件的 role 与状态（expanded / selected / checked）
- 加载、成功、错误等动态通知是否能被读屏感知

## S02.25 对比度与视觉可访问性

- 文本与控件对比度是否达到 WCAG 2.1 AA（含暗色主题、禁用态、占位符）
- 是否只用颜色传达信息
- 放大到 200% 时布局是否破损
- 动效是否尊重 `prefers-reduced-motion`

## S02.26 硬编码文本与翻译 key

- 未提取到 i18n 资源的界面文本、错误信息
- 字符串拼接组句（无法正确翻译）
- 各语言缺失的 key、无人使用的 key
- 缺翻译时的回退表现

## S02.27 复数、格式与 locale

- 复数处理是否使用 i18n 机制，而不是 `count > 1 ? 's' : ''`
- 日期、数字、货币是否按 locale 格式化
- locale 检测优先级与切换后的持久化
- 长翻译文本导致的截断与布局破损

## 错误处理与恢复

## S02.28 错误边界与整页崩溃

**定位**：错误边界组件、全局错误处理器、路由级错误页。

- 每个页面或关键区域是否有错误边界，缺失时是否整页白屏
- 错误边界的粒度：过粗整页崩溃，过细满屏报错
- 服务端全局错误处理器是否把未知异常转为合适的状态码

## S02.29 未处理的异步失败

**定位**：异步函数调用、Promise、后台任务、事件回调。

- 没有 await 也没有 catch 的 Promise
- 事件回调、定时器内部抛出的异常
- 全局 `unhandledRejection` / `uncaughtException` 的处理

## S02.30 静默吞错

**定位**：所有 catch / except 块。

- 空 catch，或只有注释
- 出错时返回 `null` / `[]` / `{}`，调用方无法区分「没有数据」和「查询失败」
- 重新抛出时丢失原始错误原因

## S02.31 超时设置

**定位**：数据库、缓存、HTTP、队列、子进程、AI 推理等所有外部调用。

- 每个外部调用是否设置了超时
- 默认超时是否远大于用户能接受的等待时间
- 上下游超时是否匹配（上游 30 秒、下游 60 秒是典型错误）
- 超时后用户看到什么

## S02.32 重试与退避

**定位**：重试逻辑、HTTP 客户端配置、队列重试配置。

- 是否指数退避并加抖动
- 重试次数与总时长上限
- 是否对不可重试的错误（4xx、校验失败）也在重试
- 被重试的操作是否幂等

## S02.33 乐观更新回滚

**定位**：先更新界面、后发请求的交互。无 UI 时跳过。

- 请求失败后界面是否回滚到原状态
- 回滚时是否告知用户
- 回滚是否覆盖了用户在等待期间的后续输入

## 性能与资源

## S02.34 内存与监听器泄漏

**定位**：事件监听、订阅、定时器、全局注册表、组件生命周期。

- 监听器、订阅、定时器是否在销毁时清理
- 只增不减的全局 Map / 数组 / 注册表
- 闭包持有大对象

## S02.35 缓存容量与淘汰

**定位**：内存缓存、本地缓存、LRU 实现。

- 是否有容量上限与淘汰策略
- TTL 是否合理，热点失效时是否并发回源
- 多实例下本地缓存的不一致

## S02.36 串行等待与 N+1

**定位**：包含多个 await 的函数、循环内的查询或请求。

- 相互独立的请求被顺序 await
- 循环内逐条查询数据库或调用接口
- 能否改为批量接口或并行

## S02.37 索引与查询效率

**定位**：数据库查询、schema 与索引定义。无数据库时跳过。

- 高频查询的过滤条件与排序字段是否有索引
- 缺少 limit 的全量查询
- 查询了用不到的大字段
- 深分页使用 offset

## S02.38 前端渲染与长列表

**定位**：列表组件、频繁更新的组件。无 UI 时跳过。

- 长列表是否虚拟化
- 不必要的重渲染（每次渲染新建对象 / 函数引用、key 使用不当）
- DOM 节点数量过大
- 渲染路径中的昂贵计算

## S02.39 包体积与资源加载

**定位**：前端构建配置、入口依赖、图片与字体。无前端时跳过。

- 整包引入大依赖（只用了其中一个函数）
- 路由级 / 组件级代码分割
- 图片尺寸、格式、懒加载
- 字体加载策略
