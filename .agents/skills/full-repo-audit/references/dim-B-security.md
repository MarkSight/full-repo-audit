# W2 安全与信任边界

先用画像里的「信任边界」清单列出**所有外部输入入口**：HTTP 路由、GraphQL resolver、
RPC/gRPC、CLI 参数、消息消费者、webhook、文件上传、定时任务读取的外部数据、
第三方回调、数据库中可被用户写入的字段（二阶注入）、反序列化点。
**每个入口逐条过 B1-B8**，没被枚举到的入口就是盲区。

---

## B1 认证与会话

1. 未受保护的入口：逐个路由/handler 确认是否有认证；默认是「拒绝」还是「允许」
   （白名单式中间件比黑名单式安全得多）。
2. 会话令牌：生成熵、存储位置、过期与续期策略、登出是否真失效（服务端撤销 vs 仅删 cookie）、
   并发会话与设备管理。
3. JWT：算法固定（禁 `alg:none`/算法混淆）、签名校验、`exp`/`aud`/`iss` 校验、
   密钥轮换、是否把可变权限塞进不可撤销的长效 token。
4. 口令与身份：哈希算法（bcrypt/scrypt/argon2，禁 md5/sha1 裸哈希）、
   盐与迭代参数、口令策略、重置流程（token 一次性、短期、绑定用户、不可枚举）。
5. 枚举与时序：登录/重置/注册的响应是否泄露账号是否存在；比较是否恒定时间。
6. 多因素与提权：MFA 流程是否可跳过；敏感操作是否要求重新认证。
7. OAuth/SSO：`state`/PKCE、redirect_uri 白名单、token 交换在服务端完成、
   账号绑定时的邮箱验证（否则可被接管）。
8. 机器身份：内部服务间调用是否认证；API key 的作用域与撤销机制。

## B2 授权与多租户隔离

1. **IDOR**：每个按 ID 取资源的查询是否附带归属条件（`user_id`/`tenant_id`/`org_id`）；
   「先取后判」模式是否在判断失败时也已泄露数据（例如错误信息里带资源名）。
2. 授权位置：是否集中在一层（middleware/policy/guard），还是散落在 handler 里靠人记得写；
   **散落即是 High**——必然有漏的。
3. 越权类型：水平（同级用户互访）、垂直（普通用户取管理员能力）、
   功能级（UI 隐藏但 API 仍可调）、字段级（返回了调用者不该看的字段）、
   批量接口（单条有校验、批量路径漏校验）。
4. 多租户：租户 ID 来源是否可被客户端伪造（必须从会话取，不能从请求体/query 取）；
   共享缓存/队列/搜索索引是否带租户隔离；跨租户关联表是否可构造越界。
5. 管理面与内部接口：debug/admin/metrics/内部端点是否暴露在公网、是否有独立认证。
6. 权限模型一致性：角色定义、权限枚举、前后端权限判断是否同一事实源；
   新增资源是否默认受保护（默认开放是设计缺陷）。
7. 代理与委托：客服代登录、API token 代表用户、agent 代表用户操作时的权限降级与审计。
8. 测试覆盖：有无「换另一个用户的 token 访问同一资源应 403/404」的测试（通常没有 → 交 W9）。

## B3 注入与输入校验

1. **校验位置**：是否在边界统一校验（schema 校验器），还是深处零散判断；
   校验后是否使用**解析后的值**而非原始输入（`parse, don't validate` 的反面是常见漏洞源）。
2. SQL/NoSQL：字符串拼接、`LIKE` 未转义、动态排序/表名、`$where`/操作符注入、
   ORM 的 raw 逃逸口。
3. 命令注入：任何 `exec`/`spawn`/`system`/`Command` 调用的参数来源；
   是否用 shell 模式拼接（应改为参数数组）。
4. 路径遍历：用户输入参与文件路径、归档解压（zip slip）、上传文件名、
   静态文件服务的 root 约束、符号链接。
5. XSS：未转义输出、`innerHTML`/`dangerouslySetInnerHTML`/`v-html`、
   模板引擎 raw 过滤器、Markdown 渲染是否 sanitize、SVG 上传、
   用户可控的 URL 进 `href`/`src`（`javascript:`）。
6. SSRF：任何「按用户给的 URL 发请求」的能力——webhook 注册、图片抓取、
   OAuth discovery、导入功能。检查：协议白名单、DNS 解析后校验（防 rebinding）、
   内网段与元数据地址（169.254.169.254、localhost、链路本地、IPv6 映射）拦截、
   **重定向后重新校验**（最常漏的一点）、出网代理/allowlist。
7. 反序列化与模板：`pickle`、Java 序列化、`yaml.load`、`eval`/`new Function`、
   服务端模板注入、原型污染（`__proto__`/`constructor`）。
8. 其他注入面：HTTP 头注入/CRLF、日志注入（伪造日志行）、
   CSV 公式注入（导出文件被 Excel 执行）、邮件头注入、LDAP/XPath、
   正则注入、Unicode 规范化绕过。
9. 二阶注入：从数据库/缓存/消息队列读出的数据再次进入危险 sink 时是否仍被当作可信。

## B4 密码学与密钥使用

1. 算法选择：禁用 MD5/SHA1（签名与口令场景）、ECB、静态 IV、
   自研加密、`Math.random()` 生成 token（应用 CSPRNG）。
2. 传输与存储加密：TLS 校验是否被关闭（`rejectUnauthorized:false`、`verify=False`）；
   静态加密需求（PII、令牌）是否落实。
3. 密钥生命周期：来源（KMS/环境）、轮换能力（能否在不停机下换）、
   旧密钥兼容、密钥与数据版本标记。
4. 签名与校验：HMAC 比较是否恒定时间；签名覆盖的字节范围是否完整（含时间戳防重放）。
5. 随机性：ID/邀请码/重置 token 的熵与可预测性；UUIDv1/自增 ID 作为安全标识。
6. 哈希用途混淆：把可逆编码（base64）当加密、把哈希当脱敏（可彩虹表反查的低熵值）。

## B5 Web / 平台加固（仅适用于有 HTTP 表面的仓库）

1. CSRF：状态变更是否需要 token 或 `SameSite` cookie + origin 校验；
   `GET` 是否会改状态。
2. 响应头：CSP（是否 `unsafe-inline`/`unsafe-eval`）、HSTS、`X-Content-Type-Options`、
   `Referrer-Policy`、`Permissions-Policy`、frame 防护。
3. CORS：是否反射任意 Origin、是否 `*` 配合 credentials、是否允许内网 origin。
4. Cookie 属性：`HttpOnly`、`Secure`、`SameSite`、作用域（Domain/Path）、
   前缀混淆与子域接管风险。
5. 开放重定向：登录后跳转、`next`/`return_to` 参数的白名单。
6. 文件上传：类型校验（按内容嗅探而非扩展名）、大小限制、存储位置不可执行、
   下载时的 `Content-Disposition` 与 `Content-Type`、文件名规范化、病毒/内容扫描需求。
7. 缓存与隐私：私有响应是否被 CDN/浏览器缓存（`Cache-Control: private/no-store`）；
   URL 中是否携带敏感参数（会进日志与 Referer）。
8. 客户端存储：token 放 `localStorage` 的 XSS 风险权衡；
   敏感数据进 IndexedDB/sessionStorage。
9. 错误页与信息泄露：堆栈、SQL 错误、内部路径、版本号、源码映射泄露到生产。

## B6 滥用、配额与资源保护

1. 限流：是否存在；维度（IP/用户/租户/端点）、算法、共享存储下的正确性、
   代理后真实 IP 获取（`X-Forwarded-For` 信任链）。
2. 昂贵操作保护：搜索、导出、报表、AI 调用、图像处理、批量接口是否有配额与成本上限。
3. 输入规模上限：请求体大小、数组长度、嵌套深度（JSON bomb）、分页 `limit` 上限、
   文件大小与解压后大小（zip bomb）、GraphQL 查询深度与复杂度。
4. ReDoS：用户输入参与的正则是否含嵌套量词；是否有超时保护。
5. 并发滥用：同一用户并发触发昂贵任务的去重；排队与背压；
   队列无界增长；重试风暴（与 D2 联动）。
6. 枚举与爬取：批量查询接口是否可遍历全量数据；顺序 ID 可被遍历。
7. 计费与额度：付费资源的计量与硬上限是否在服务端执行（客户端限制不算）。

## B7 隐私、PII 与数据留存

1. PII 盘点：哪些字段是个人数据（含 IP、设备 ID、精确位置、生物特征、
   聊天内容、上传文件）；是否有字段级标注。
2. 最小化：是否收集了用不上的数据；第三方 SDK 是否顺带采集。
3. 日志与遥测：PII 是否进日志/错误上报/分析事件；是否脱敏；日志保留期。
4. 用户权利：导出、删除（含级联与备份中的副本）、更正、同意撤回是否有实现路径。
5. 留存与清理：是否有 TTL / 定期清理任务；软删除数据是否永久堆积；
   临时文件与上传中间产物清理。
6. 跨境与存储位置、子处理方清单（有合规要求的仓库）。
7. 共享与导出：导出文件的访问控制与链接有效期；分享链接是否可猜测。
8. AI/第三方处理：用户内容是否被送往第三方模型/服务；是否有开关与告知。

## B8 集成、Webhook 与回调

1. 入站 webhook：签名校验（存在性 + 恒定时间比较 + 覆盖完整 body）、
   时间戳防重放、幂等键、未知事件类型处理、校验失败时的日志与告警。
2. 出站 webhook/回调：目标 URL 的 SSRF 约束（与 B3-6 联动）、重试策略、
   失败投递的死信与可观测性、发送内容中的敏感字段。
3. 第三方令牌：作用域最小化、存储加密、刷新失败的降级、撤销处理。
4. 回调顺序与乱序：事件乱序到达、重复到达、丢失时的一致性（与 C4 联动）。
5. 供应商故障：超时、降级、熔断（与 D2 联动）；供应商返回异常数据时的校验
   （第三方响应同样是不可信输入）。
6. 内部服务间调用：是否假设内网即可信；mTLS/签名；服务间越权。
