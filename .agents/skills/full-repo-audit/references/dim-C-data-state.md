# W3 数据与状态正确性

**适用**：有持久化（数据库/文件/对象存储/缓存/队列）或有显式状态机的仓库。
纯无状态工具库可整波标「不适用」。

审查方法：先列出**所有写路径**（创建/更新/删除/批量导入/迁移/后台任务），
每条写路径过 C1-C5；再列出**所有读路径**过 C3/C6。

---

## C1 事务与原子性

1. **多步写是否在一个事务内**：典型反模式 `delete + insert`、
   「先写主表再写关联表」、「写 DB 再发消息」。
2. **事务边界是否覆盖全部相关写**：事务对象是否一路传递到下层函数，
   还是下层偷偷用了全局连接（这会让事务形同虚设——**高频真实缺陷**）。
3. **事务内做外部 IO**：事务里发 HTTP、等锁、跑长任务、调 AI 模型
   → 长事务占用连接、超时回滚丢数据。
4. **双写一致性**：DB + 缓存、DB + 搜索索引、DB + 对象存储、DB + 消息队列。
   需要 outbox/补偿/幂等重放，否则必然漂移。
5. **隔离级别与锁**：是否依赖了实际未提供的隔离保证；
   `SELECT ... FOR UPDATE` 的使用与死锁顺序；乐观锁版本号冲突处理。
6. **回滚正确性**：失败后已产生的副作用（已发邮件、已扣费、已写文件、已建外部资源）
   是否有补偿；`finally` 中的清理是否会吞掉原始错误。
7. **批量操作**：部分成功的语义是否明确（全失败 / 部分成功并报告 / 逐条事务）；
   大批量是否分块以避免超长事务。
8. **嵌套事务/保存点**语义是否被正确理解（多数驱动下嵌套 begin 不是你想的那样）。

## C2 迁移与向后兼容

1. **迁移可逆性**：是否有 down/回滚方案；不可逆操作（drop column/table、改类型）
   是否有两阶段方案（先加新列双写 → 回填 → 切读 → 再删旧列）。
2. **与代码部署的时序**：迁移先跑还是代码先上？旧代码遇到新 schema、
   新代码遇到旧 schema 是否都能活（滚动发布期必然同时存在）。
3. **大表迁移风险**：锁表、全表重写、加索引阻塞、超时；是否有批量/在线 DDL 方案。
4. **数据回填**：回填脚本是否幂等、可中断续跑、有进度与限速；
   失败一半的状态是否可恢复。
5. **迁移完整性**：迁移文件是否与 schema 定义一致（schema 被手改过？）；
   迁移序号冲突/重复；是否有「在迁移中引用应用代码」的脆弱耦合。
6. **历史数据兼容**：老数据中的 null、旧枚举值、旧格式 JSON、
   已不存在的外键引用；新代码是否假设了只有新数据才有的字段。
7. **跨版本数据格式**：持久化的序列化结构（JSON 列、缓存值、队列消息体）
   是否带版本字段；读旧版本的兼容分支是否存在且被测试。
8. **种子与夹具**：seed 数据是否与迁移同步；测试夹具是否落后于 schema（与 E4 联动）。

## C3 Schema、约束、索引与查询

1. **约束缺失**：该有的 NOT NULL / UNIQUE / 外键 / CHECK 是否只存在于应用层；
   唯一性仅靠「先查再插」（竞态下必然重复 → 与 C4 联动）。
2. **级联行为**：删除父记录时子记录的处理（级联删 / 置空 / 拒绝）是否与业务意图一致；
   孤儿数据是否已存在。
3. **索引**：高频查询条件与排序是否有支撑索引；复合索引列序是否匹配查询；
   冗余/重复索引；外键是否缺索引；大表全表扫描。
4. **查询效率与正确性**：N+1、缺 limit 的全量查询、`SELECT *` 传输无用大字段、
   分页用 offset 在深翻页下的性能与漏/重问题（应考虑游标分页）。
5. **类型与精度**：金额用浮点（必须定点/整数分）、时间戳带不带时区、
   枚举用字符串还是受约束类型、JSON 列中缺乏校验的自由结构。
6. **字符集与排序规则**：大小写敏感性、unicode 比较、emoji/四字节字符支持、
   唯一索引在不同 collation 下的行为。
7. **软删除一致性**：所有查询是否都过滤了已删除记录（遗漏处会泄露已删数据）；
   唯一约束与软删除的冲突。
8. **连接与资源**：连接池大小与并发匹配、泄漏的连接/游标、长事务占用、
   查询超时设置（与 D3/F2 联动）。

## C4 并发与竞态

1. **TOCTOU**：「检查后行动」序列（查余额→扣款、查重→插入、查状态→改状态）
   是否有原子保障（DB 约束、条件更新 `WHERE status = 'old'`、锁）。
2. **幂等性**：可重复触发的入口（重试、用户双击、webhook 重投、队列重放）
   是否有幂等键；相同请求重放两次的后果是否可接受。
3. **任务去重**：同一任务是否可能被并发执行两次（多实例、多 worker、多标签页）；
   租约/心跳/可见性超时设置是否合理。
4. **队列语义**：at-least-once 下消费者是否幂等；顺序依赖是否成立；
   死信与重试上限；消费失败后的消息可见性。
5. **分布式锁**：是否有 TTL、是否可被非持有者释放、续约失败后的行为、
   单点故障下的正确性。
6. **进程内并发**：共享可变状态、非线程/协程安全的缓存、
   模块级单例在并发请求间泄漏用户上下文（**严重且常见**）。
7. **多客户端竞态**：同一用户多标签页/多设备同时编辑（最后写入覆盖 vs 冲突检测）；
   跨标签页通信与本地存储写冲突；离线编辑合并。
8. **启动竞态**：依赖未就绪就开始服务（DB 未连、缓存未热、配置未加载）；
   多实例同时跑「启动时初始化」逻辑（建表、写默认数据）。

## C5 状态机与生命周期

1. **状态定义完整性**：所有状态是否显式枚举；是否存在「隐含状态」
   由多个布尔字段组合表达（必然出现非法组合）。
2. **转移合法性**：非法转移是否被拒绝（而不是静默允许）；
   转移是否在一处集中判定；是否有转移审计记录。
3. **终态与卡死**：是否存在无出路的中间态（`processing` 永不结束）；
   有无超时清理/看门狗；重启后 in-flight 状态如何恢复。
4. **并发转移**：两个请求同时推进状态（条件更新保障）；
   状态与副作用的顺序（先改状态再发副作用，还是反过来）。
5. **取消与回退**：用户取消、管理员撤销、系统回滚时的状态一致性；
   已产生的外部副作用如何处理。
6. **长生命周期对象**：会话、订阅、审批流、多步表单、AI 对话回合的
   超时、续期、过期清理。
7. **状态可观测性**：能否从数据直接回答「现在卡在哪一步、为什么」（与 D4 联动）。

## C6 缓存与一致性

1. **失效策略**：写后是否失效/更新相关键；失效是否覆盖所有派生键
   （列表缓存、聚合缓存、分页缓存最易漏）。
2. **键设计**：是否包含所有影响结果的维度（用户/租户/语言/权限/版本）。
   **缺租户或权限维度的缓存键 = 越权泄露（Critical）**。
3. **多层缓存**：浏览器 / CDN / 应用 / ORM / DB 各层 TTL 是否协调；
   私有数据是否被共享层缓存（与 B5-7 联动）。
4. **一致性窗口**：用户写入后立刻读能否看到自己的改动（read-your-writes）；
   过期数据是否会被展示为「已保存」。
5. **击穿与雪崩**：热点键失效瞬间的并发回源（需 singleflight/互斥）；
   TTL 是否加抖动；缓存不可用时是否降级到源（还是整体报错）。
6. **负缓存与错误缓存**：是否把错误/空结果缓存了很久。
7. **淘汰与容量**：内存缓存是否有上限与淘汰（无上限 = 内存泄漏，与 D3 联动）；
   本地缓存在多实例下的不一致。
8. **缓存正确性测试**：有无「写后读」与「失效」测试（通常没有 → 交 W9）。

## C7 备份、恢复与数据丢失路径

**适用**：自管数据存储的仓库；全托管则记录「由供应商负责」并检查配置。

1. 备份存在性与频率、保留期、异地副本；备份是否包含对象存储与配置。
2. **恢复演练**：有无恢复步骤文档与验证记录（没演练过的备份等于没有备份）；RPO/RTO 是否明确。
3. 备份加密与访问控制（备份往往是最弱的一环）。
4. **不可逆操作的防护**：硬删除接口、批量删除脚本、`TRUNCATE`、
   迁移中的 drop；是否有确认机制、软删除过渡期、审计记录。
5. 数据丢失路径盘点：未提交事务、缓冲未落盘（fsync/WAL checkpoint）、
   进程被杀时的内存中数据、临时目录被清理、上传中断的孤儿文件。
6. 导入导出往返一致性（导出再导入是否无损）。

## C8 时间、精度、单位与编码

常被整轮审查完全忽略，但产生的 bug 极难排查。

1. **时区**：存储是否统一 UTC；展示是否按用户时区；
   「今天/本月」边界按谁的时区算；夏令时与闰秒；跨时区定时任务。
2. **时钟**：是否用单调时钟测量耗时（墙钟会回跳）；
   客户端时间是否被信任（用于业务判断即是漏洞）；时间比较的时钟偏移容忍。
3. **日期格式**：序列化格式是否统一（ISO 8601 带偏移）；
   字符串日期比较；解析无时区字符串时的默认假设。
4. **金额与数值精度**：浮点表示货币、四舍五入规则与方向、
   累加顺序误差、百分比与汇率换算、整数溢出、除零。
5. **单位**：毫秒/秒混用（超时与 TTL 的经典事故）、字节/KB、度量单位缺后缀命名。
6. **编码**：UTF-8 端到端、字符串长度按字节还是码点（截断导致乱码）、
   emoji 与组合字符、大小写折叠与 unicode 规范化（也影响安全比较）、
   换行符与 BOM、URL/HTML/JSON 多层编码解码顺序。
7. **排序与比较**：本地化排序、数字字符串排序、稳定排序依赖。
8. **ID 与序列**：ID 生成的唯一性与可排序性、分布式下的冲突、
   把 ID 当可猜测资源标识（与 B2 联动）。
